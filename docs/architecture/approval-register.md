## Review record

Its start used `feat/spec-001-repository` from `dev` at `3b74bd3`; the measured foundation is now available in the current `dev` baseline `f5b7cf1`.

G0 current scope: on 2026-10-18 the user authorised starting SPEC-002 offline shared contracts. Branch: `feat/spec-002-contracts` from `dev` at `f5b7cf1`. [ADR-0002](decisions/ADR-0002-shared-contracts.md) and [the SPEC-002 implementation plan](plans/SPEC-002.md) record the accepted scope and bounded offline profile. This is start authority only; no SPEC-002 commit, push, merge or deployment is authorised. Work remains one specification at a time.

D-02's real-source choice and D-04/05/06/08/09 remain **open**. D-03 and D-07 are accepted only for the contract identity/fingerprint rules and finite offline profile above; their SQL/control and operating-policy portions remain open. SPEC-002 may define common URL/evidence/outcome shapes with synthetic profile validation, but cannot select a real normalization policy, storage/retention guarantee, retry/retirement policy or production schema. Those choices retain their owning specifications' gates.

Future approvals should reference this register and the graph/plan revisions. Decisions may be resolved separately to unblock affected specs. Promote only those specs whose requirements and acceptance examples are complete; preserve unresolved items as blockers. For each material choice create an ADR from [the template](../templates/adr-template.md), link the affected requirement/spec IDs, and record the user's actual decision. Do not ask the user to reconfirm an already approved choice without a material change; the next-specification start gate remains explicit.
