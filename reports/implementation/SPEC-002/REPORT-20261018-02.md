## Changes and rationale

- `schemas.ts` defines draft-07 message/scalar schemas; types are inferred from the same definitions. Decimal-string SQL IDs retain full signed BIGINT precision; UUID logical/event IDs remain separate from opaque physical/provider identifiers.
- `validation.ts` rejects coercion, defaults, field removal, unsupported versions and unknown envelope fields. Trusted profiles are supplied independently and snapshotted. Extraction checks match profile, full manifest, assignment/fence, build and physical run before accepting source records. Source data remains unchanged.
- Discovery checks retain separate discovery/target ownership and correlate to approved target rules. Coverage requires the expected partition set and consistent per-partition/aggregate counts; limits and cancellation cannot claim complete coverage. Summaries cannot claim more emitted/processed work than assigned.
- `json.ts` bounds UTF-8 bytes, depth, object members and strings; rejects duplicate decoded raw keys, invalid Unicode/non-finite values and non-JSON parsed objects without invoking getters/proxies/serialization hooks. Diagnostics contain fixed codes and known/redacted paths, never rejected values.
- `fingerprint.ts` canonicalizes the complete event. Manifest hashing excludes only its own digest and includes parser/normalization/limits/evidence settings. Replay/conflict/new-event classification is pure; ID allocation, quarantine, ownership and SQL writes remain downstream.
- Root `npm test`/`check` now include harness, unit and contract suites. Type checking allows explicit `.ts` source imports and enforces erasable syntax for the pinned Node 24 runtime. Package exports are consumed both through Vitest and native Node.
- Added pinned Ajv `8.20.0`, canonicalize `5.1.0`, jsonc-parser `3.3.1`; schema-derived types use development dependency json-schema-to-ts `3.1.1`. These avoid handwritten schema/type duplication, a custom JSON parser and a custom canonicalizer. No remote schema loading or schema registry service exists.
